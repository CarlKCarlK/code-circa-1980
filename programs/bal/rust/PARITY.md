# Rust port: parity with Chemistry Balancer II

Reference: **v20**, tape23b save 1 (identical to save 2), the latest recovered
Chemistry Balancer II. The port replicates its algorithm, not its BASIC structure.
Control flow is rewritten; small numeric differences are acceptable by design.

## Same steps

| Step | BASIC lines | Rust |
|---|---|---|
| Upper-case input; reject illegal characters; `-` only after `@` | 205–215 | `parse::parse` |
| Element = letter plus optional second letter; `.` and space separate | 1000–1280 | `parse::parse_compound` |
| Subscripts multiply the preceding element or `)` group; nesting ≤ 9 | 320–470 | `parse::parse_compound` |
| Reactant columns positive, product columns negative; repeats summed | 440, 5040 | `parse::parse` |
| Element on only one side → ALCHEMY | 480–500, 7500 | `solve::solve` |
| Drop element rows proportional to an earlier row | 505–570 | `drop_proportional_rows` |
| Split into independent sub-equations ("MIXED EQUATIONS"), solve each | 585–910 | `connected_blocks` |
| More compounds than elements + 1 → AMBIGUOUS | 3001 | `solve_block` |
| Last compound fixed at 1 and moved to the right-hand side | 3091 | `solve_block` |
| Exact fraction Gauss–Jordan; GCD-reduced numerator/denominator | 3115–3230, 4000 | `solve_block`, `fraction` |
| Zero row moves to the end; zero pivot swaps with a lower row | 5510–5530, 11000 | `solve_block` |
| Leftover rows must have zero right-hand side → MULTIPLE REPLACEMENT | 3250–3260 | `solve_block` |
| Coefficients must be positive → NEGATIVE SOLUTION; above 1E16 → OVERFLOW | 940 | `to_whole_numbers` |
| Output `n( compound )`, `+`, `-^`, `< >` for parentheses | 7000–7220 | `Balanced::trs80_text` |

## Verified

`app/tests/balancer-engine.test.mjs` compares the WebAssembly build with v20's
output for ten reference equations recorded in the emulator
(`modern/parity-fixtures.json`, regenerated by `npm run record:balancer`) and
runs v20 live for two of them. All match, ignoring whitespace from the
original's 62-column line wrapping. `cargo test` covers the same equations plus
error cases, nested groups and charges.

## Known differences

- **Integer scaling.** The original multiplies the solved fractions by the
  product of their denominators. The port uses the least common multiple and then
  divides by the common factor, so it always prints the smallest whole numbers.
  The reference equations give identical results.
- **Arithmetic range.** BASIC used double-precision floating point (about 16
  digits) for numerators and denominators. The port uses exact `i64` values with
  `i128` intermediate products. Both report OVERFLOW above 10¹⁶; near that limit
  the original could lose precision first.
- **UNDERFLOW** (error 11, a non-integer result) cannot occur with exact scaling.
- **Unused paths.** v20 still contains acid/base code (RX, lines 265–290,
  7600–7610, 9500–9520) that never runs because RX stays 0. It is not ported.
- **Mixed equations.** The original printed "WARNING: MIXED EQUATIONS" and
  continued. The port returns a `mixed` flag that the browser shows as a note.
- **Charge.** `@` is a pseudo-element, as in the original. The modern display
  shows `FE@3` as Fe³⁺; this is presentation only.
- **Display.** The browser shows modern notation (`C₃H₈ + 5 O₂ → …`) and the
  element equations, as well as the 1981 printout line.
